# 增强方法接入验证

## VisCRA 混合 SDPA 与按需提取（当前）

2026-09-18 按用户确认恢复视觉编码器 SDPA、文本解码器 eager，并恢复按需提取。
所有文本层仍执行 eager 前向；仅在指定的第 18 层读取最后文本 token 对图像 token 的
平均注意力，立即复制到 CPU，不累计保存各层完整注意力矩阵。成功或异常后均移除 hook。
单次前向不保留 KV cache。模型仍按原版方式在可见 GPU 上分配权重。

源图分辨率、四边各一行/列置零、最终使用 `rephrased_question` 均保留：
512 使用 18×18 注意力网格、5×5 窗口；2048 使用 73×73 网格、12×12 窗口。
本轮使用 GPU 0、1（各 A100 40GB）及同一合成中性图片验证，没有调用辅助 API。

| 检查 | 结果 |
| --- | --- |
| 512，混合后端＋按需提取 | 成功；遮挡框 `[313, 57, 455, 199]` |
| 2048，混合后端＋按需提取 | 成功；遮挡框 `[449, 1234, 786, 1571]`，337×337 |
| 2048 峰值已分配显存 | GPU 0 / GPU 1：14.51 / 15.54 GiB |
| 512 按需提取与完整返回的对照 | 同一混合模型、同一输入，第 18 层所需注意力逐元素一致 |
| 512 混合后端与全 eager 的对照 | 同一加载模型切换视觉后端，注意力和遮挡框均有差异 |

必须区分两类变化：按需提取的上述对照结果一致；视觉 SDPA 与 eager 的浮点计算路径不同，
不能保证逐元素一致或选择同一个最高分窗口。512 对照中，全 eager 遮挡框为
`[114, 313, 256, 455]`，混合后端为 `[313, 57, 455, 199]`；最后文本 token 对图像的平均注意力
最大绝对差为 0.0007677，平均绝对差为 0.00004535，相对 L1 差约 22.45%。
该单张合成图的结果不能用于推断攻击成功率或全数据集差异。

本轮也验证了只切换视觉 SDPA、仍完整返回所有文本层注意力的方案：512 成功，2048 在
文本解码器 GPU 1 的 softmax 处仍 OOM，尝试分配 2.99 GiB 时可用约 758 MiB。
因此双卡通过结果依赖“混合后端＋按需提取”同时启用，不能仅归因于视觉 SDPA。
完整注意力方案失败前峰值为 28.06 / 35.11 GiB；这些数值不是成功运行所需峰值。

随后补测“全 eager＋按需提取”，仍使用 GPU 0、1 和相同中性图片：512 成功，
所需注意力与全 eager 完整返回逐元素一致，遮挡框为 `[114, 313, 256, 455]`；
2048 仍在视觉编码器 FP32 softmax 处 OOM，尝试额外分配 27.08 GiB 时该卡可用
17.47 GiB，失败前两卡峰值已分配显存为 34.25 / 7.82 GiB。
按需提取减少跨层累计保存，不能消除单个 eager 算子计算时的临时矩阵。
因此这一组合本身可用，但在当前双 A100 40GB、原分辨率和现有层分配下仍无法处理 2048。

当前环境的 Transformers SDPA 接口返回 `(attn_output, None)`，不返回可提取的视觉注意力
权重。VisCRA 使用的是文本解码器第 18 层最后文本 token 对图像 token 的注意力，
将这组权重重排为二维遮挡热图；它与视觉编码器内部图像 token 之间的注意力矩阵不同。
混合模式用视觉 SDPA 计算图像特征，同时从文本 eager 层提取所需热图。

机器记录保存在原验证 run 下的 `viscra_mixed_two_gpu_validation.json`，
日志为 `viscra_mixed_full_attention_validation.log` 和 `viscra_mixed_selected_validation.log`。
补测日志为 `viscra_eager_selected_validation.log`，机器记录中的
`eager_selected_comparison` 保存该组合的结果与异常栈。
记录包含后端对照、失败路径、最终双卡结果和完整 device_map。
80 项离线测试全部通过，覆盖新旧模型布局的按需提取、成功与失败时的 hook 清理、
分尺寸窗口和四边过滤。实测进程结束后，GPU 0、1 的显存占用均回到 0 MiB。
源码变化会使 VisCRA 的旧缓存失效；本轮没有重生成已有 benchmark 的增强样本。

512 的 5×5、2048 的 12×12，以及非方图的默认窗口。80 项离线测试全部通过。
五卡实测命令在启动前被中断；检查时 GPU 0、1、2、6、7 均无显存占用。

| 输入与窗口 | 结果 | GPU 0 / GPU 1 峰值已分配显存 |
| --- | --- | --- |
| 512×512，5×5 | 成功，18×18 注意力网格，遮挡框 `[114, 313, 256, 455]` | 7.82 / 8.00 GiB |
| 2048×2048，12×12 | CUDA OOM，尚未执行窗口选择 | 34.61 / 7.82 GiB（失败前峰值） |

不能直接承接这个单层算子的分配。原版每卡 8 GiB 权重预算使 `lm_head` 自动卸载到磁盘，
完整 device_map 已保存在验证记录中。上述峰值是已成功分配的最大值，不代表成功运行 2048 所需峰值。
进程结束后确认 GPU 0、1 的显存占用均回到 0 MiB。测试使用合成中性图片，未调用辅助 API，
未重生成已有增强样本；未切换 SDPA、缩小输入或增加 GPU。

机器可读结果与完整日志保存在原验证 run 下的 `viscra_two_gpu_validation.json` 和
`viscra_two_gpu_validation.log`。
下节 23.39 GiB 显存和 2048/5×5 遮挡结果属于更早版本，不能作为当前版本的验证结果。
