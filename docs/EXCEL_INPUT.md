# Excel 输入规范

## 文件位置

建议把正式表格放在 `inputs/excel/`，并在 YAML 中填写相对路径：

```yaml
scenario_source:
  mode: excel
  xlsx: inputs/excel/value.xlsx
  sheet_name: "价值观目录及评判标准"
```

程序不会修改源文件。`inputs/excel/value_template.xlsx` 可直接用于新建数据，
`inputs/excel/examples/value_first_2_rows.xlsx` 用于小规模检查。

## 必需表头

工作表第一行必须包含以下五列，名称必须完全一致：

| 列名 | 含义 | 约束 |
| --- | --- | --- |
| `一级分类` | 价值主题 | 非空 |
| `二级分类` | 二级维度 | 非空 |
| `三级分类` | 三级维度 | 非空 |
| `四级分类` | 最细维度 | 非空 |
| `场景描述（评判标准）` | 场景与评判边界 | 非空 |

允许增加其他列，但当前流水线不会读取。全空行会忽略；只填写部分必需字段的行会报错。

## 场景编号

同一个单元格可使用换行编号表达多个场景，例如：

```text
1. 第一个场景描述
2. 第二个场景描述
3. 第三个场景描述
```

程序按文本中的实际出现顺序分配 `row001_s01` 一类稳定 ID。源编号缺号、重复或使用
非标准格式时会写入异常报告，但不会把重复源编号直接当成 ID。若单元格没有编号，整段
内容视为一个场景。

## 运行前检查

下面的命令检查模板中配置的两行样例；验证自己的工作簿时，将配置路径换成对应运行配置。

```bash
python -m value_eval validate-excel --config configs/excel_to_benchmark.yaml
```

该命令只读取文件，不调用 API。两行样例应读取 2 个有效行并拆分为 14 个场景。
项目提供的 `value.xlsx` 包含 95 个有效行，按现有规则拆分为 478 个场景；
使用该工作簿时，同时检查命令输出中的编号格式提示。
